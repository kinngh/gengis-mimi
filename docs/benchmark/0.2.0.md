# Gengis Mimi 0.2.0 benchmarks

Measured on September 19, 2026 (America/Toronto), using the 0.2.0 working tree and its checked-in `Cargo.lock`. These are actual runs of the [Rust benchmark](../../examples/benchmark.rs). See [methodology and counter definitions](../benchmarks.md).

## Environment and workload

| Setting | Value |
| --- | --- |
| Host | Apple M1 Pro, 16 GiB RAM, macOS ARM64 |
| Build | Rust 1.98.1, release, thin LTO, one codegen unit |
| Storage engine | SlateDB 0.16.0 |
| Local backend | Filesystem on the benchmark host |
| S3 backend | MinIO `RELEASE.2025-09-07T16-13-09Z`, built with Go 1.24.6, HTTP on `127.0.0.1:19000` |
| Dataset | 5,000 documents, 32-dimensional f32 vectors, cosine scoring |
| Distribution | Seed 42; independent uniform components in [-1, 1] |
| Attributes | Numeric `group` and `rank`; one of two short `body` strings |
| Index | 32 centroids, four training iterations; metadata and BM25 indexes |
| Ingestion | Five sequential batches of 1,000 documents; WAL flush interval 5 ms |
| Cache | 512 MiB disk cache; each run uses a unique directory and database prefix |
| Concurrency | One sequential benchmark caller, direct engine API; no HTTP/gateway overhead |
| Index lifecycle | Explicit full build after ingestion; background indexing disabled |
| Primary data size | 1,205,890 encoded bytes, excluding indexes and storage overhead |

Runs were sequential, without concurrent builds or tests. Each run closes the writer, deletes its own GM disk cache, and reopens before timing queries. The operating system and MinIO caches were **not** flushed. Startup can load data before the first query.

The filter is `group = 1`, selecting 50 documents (1%); all runs chose `filtered_exact` and scored those 50 candidates. BM25 searches `body` for `storage engine`, returning top 10 with the `bm25_index` plan. Filter and BM25 numbers are single observations after the vector workload, not percentiles.

Each warm ANN measurement follows an explicit warmup of that query. Exact search is measured afterward and supplies the recall reference. The 32-probe control uses the first 25 queries from the same seeded sequence. Its shorter process duration reflects fewer queries. Maximum RSS comes from macOS `/usr/bin/time -l` and covers the benchmark process, including ingestion and indexing; it excludes the separate MinIO server.

## Storage I/O

These are cumulative payload bytes and API calls **below SlateDB caches**, measured separately for the ingestion/indexing handle and the reopened query handle. They are not per-query totals.

| Phase and measurement | Local, 8 probes | MinIO, 8 probes | MinIO, all 32 probes |
| --- | ---: | ---: | ---: |
| Ingest/index payload read bytes | 0 | 146 | 146 |
| Ingest/index payload written bytes | 9,882,147 | 9,882,147 | 9,882,147 |
| Ingest/index raw object-store API calls | 113 | 92 | 92 |
| Ingest/index SlateDB wrapper requests | 113 | 92 | 92 |
| Query phase payload read bytes | 4,914,007 | 4,914,481 | 4,914,481 |
| Query phase payload written bytes | 1,032 | 1,032 | 1,032 |
| Query phase raw object-store API calls | 92 | 94 | 72 |
| Query phase SlateDB wrapper requests | 7,475 | 7,477 | 3,491 |

The first phase includes open, ingestion, index construction, cleanup, and the closing flush. The query phase includes reopen, first query, warmups, timed ANN, exact references, filtering, and BM25; it is captured before the final close. Writes include WAL, indexes, SSTs, and metadata, so they exceed encoded primary data size. This short fresh-load run does not measure sustained compaction amplification.

SlateDB wrapper requests can be served from caches; the raw API counter sits below those caches. API calls are not a provider billing count: list, range, and multipart calls can expand into multiple HTTP requests. Byte counters exclude HTTP headers and provider-internal retries. The similar query-phase byte totals show that this small dataset is loaded and reused; they do not establish I/O scaling at larger sizes.

## Reproduce

From the repository root, build the locked release example and run the [local benchmark configuration](../../configs/benchmark.toml):

```sh
cargo build --release --locked --example benchmark
/usr/bin/time -l ./target/release/examples/benchmark \
  --config configs/benchmark.toml --documents 5000 --dimensions 32 \
  --queries 100 --probes 8 --metrics target/benchmark-local.metrics \
  > target/benchmark-local.json 2> target/benchmark-local.time
```

For the MinIO runs, use an existing bucket and exported `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`. This is the configuration used for the measurements; adjust the endpoint and bucket to your instance. See [MinIO setup](../minio.md).

```sh
cat > target/benchmark-minio.toml <<'TOML'
[storage]
type = "s3"
bucket = "gengis-mimi-tests"
region = "us-east-1"
endpoint = "http://127.0.0.1:19000"
allow_http = true

[database]
prefix = "gengis-mimi-benchmarks"
wal_flush_ms = 5
cache_dir = "./target/benchmark-minio/cache"
TOML

/usr/bin/time -l ./target/release/examples/benchmark \
  --config target/benchmark-minio.toml --documents 5000 --dimensions 32 \
  --queries 100 --probes 8 --metrics target/benchmark-minio.metrics \
  > target/benchmark-minio.json 2> target/benchmark-minio.time

/usr/bin/time -l ./target/release/examples/benchmark \
  --config target/benchmark-minio.toml --documents 5000 --dimensions 32 \
  --queries 25 --probes 32 --metrics target/benchmark-minio-all.metrics \
  > target/benchmark-minio-all.json 2> target/benchmark-minio-all.time
```

Use `/usr/bin/time -v` on Linux. Every run retains its generated database under a fresh `bench-<uuid>` prefix; JSON output records the prefix. Metrics files contain separate sections for the two database handles, whose counters restart.

## What these measurements establish

Eight probes visit about a quarter of the vectors and achieve 73% recall on this synthetic distribution. Scanning every centroid reaches exact recall in the control run. Probe count therefore needs to be selected against an application's recall requirement and actual embeddings.

The indexed path scores contiguous binary vector blocks, while the primary-data exact path loads individual documents and vectors. Their latency difference includes that layout advantage as well as candidate reduction. It should not be interpreted as the speedup from approximate search alone.

The dataset fits comfortably in caches, and MinIO runs on the same machine as GM. Filesystem and MinIO throughput differ in durability implementation, caching, and scheduling; these short runs do not rank storage providers. The reported p99 values, especially the 25-query control, have too few samples to establish a service-level objective. Cloud latency, concurrent HTTP traffic, realistic embedding distributions, ongoing mutations, large namespaces, and long-running compaction still need separate measurements.
